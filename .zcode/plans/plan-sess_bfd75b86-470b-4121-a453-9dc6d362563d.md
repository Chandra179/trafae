## Create `docs/vedic-astrology-combinations.yaml` + validation

One new file (no code in the repo), plus a one-line cross-link added to the Vedic doc's §10.

### Proposed format (7 sections)

1. **Header comment + `meta`** — explains the product-not-list design; records conventions (Lahiri ayanamsa, true node, whole-sign houses, 365.2425-day dasha years, sidereal 0–360° angles) as fields a consumer can read.
2. **`grahas`** — all 9 with stable snake_case ids (`surya` … `ketu`) + english names; `independent: false` and the rule `ketu = (rahu + 180) mod 360` on Ketu — encoding the "8 independent axes" fact machine-readably.
3. **`rashis`** — all 12 (index, id, english, start_deg).
4. **`nakshatras`** — all 27 fully enumerated with lord and start_deg, plus `nakshatra_lord_cycle` and the exact pada arithmetic (800/200 arcmin) in comments.
5. **`bhavas`** — whole-sign rule as a formula string, marked `derived: true`.
6. **`vimshottari`** — the full 9-lord cycle with years, total 120, `distinct_timelines: 27`.
7. **`vargas`** — the 16 classical divisional charts (D1–D60), marked derived.
8. **`combination_space`** — the answer to the earlier "how many combinations" question as data: `independent_axes` (8 + 1), and `cardinality_by_grid` with **exact integers** (12⁹ = 5,159,780,352; 27⁹ = 7,625,597,484,987; 108⁹ = 1,999,004,627,104,432,128; 360⁹ = 1.0156×10²³; continuous = uncountably infinite) and the fixed-space/growth rationale.
9. **`instance_example`** — the §9 worked chart (1990-11-15, 09:00 IST, New Delhi) encoded as one combination: birth/ayanamsa/ascendant, then each graha as `{graha, tropical_deg, sidereal_deg, rashi, nakshatra, pada, house}` (Ketu flagged derived), then the Vimshottari state at birth.
